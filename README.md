# ☕ Java Code Structure

Each problem is implemented as a **static method**.

The daily/topic Java files contain the actual problem-solving logic.

For example:

```java
import java.util.HashMap;
class MonthDate {
    // ! =============== LC1. Two Sum ================
    public static int[] twoSumOptimal(int[] nums, int target) {
        HashMap<Integer, Integer> map = new HashMap<>();

        for (int i = 0; i < nums.length; i++) {
            int complement = target - nums[i];

            if (map.containsKey(complement)) {
                return new int[] {map.get(complement),i};
            }
            map.put(nums[i], i);
        }
        return new int[] {};
    }
}
```

The actual execution is handled separately through `Demo.java`.

# 🧪 Demo.java

`Demo.java` acts as the **execution and testing file**.

The problem-solving methods are written inside the corresponding Java files and then called from `Demo.java`.

### Example

```java
import java.util.Arrays;
public class Demo {
    public static void main(String[] args) {

        int[] nums = {2, 7, 11, 15};
        int target = 9;

        int[] result = Aug15.twoSumOptimal(nums, target);

        System.out.println(Arrays.toString(result));
    }
}
```

### 🧩 Execution Flow

```text
┌─────────────────────────┐
│   Problem Implementation │

└────────────┬────────────┘
             │
             ▼
┌─────────────────────────┐

             │
             ▼

│        Demo.java         │
│    Test / Execute Code   │
└────────────┬────────────┘
             │
             ▼
        ✅ Output
```

# 🏷️ Problem Naming Convention

Every problem is separated using a consistent comment format:

```java
// ! =============== LC412. Fizz Buzz ================
```

The prefix identifies the **source of the problem**.

<details>
<summary><b>🏷️ Problem Source Prefixes</b></summary>

<br>

| Prefix    | Platform                                     |
| --------- | -------------------------------------------- |
| `LC`      | LeetCode                                     |
| `GFG`     | GeeksForGeeks                                |
| `H`       | HackerRank                                   |
| `CC`      | CodeChef                                     |
| `CF`      | Codeforces                                   |
| No Prefix | Self Practice / Fundamental / Custom Problem |

</details>

### Examples

```java
// ! =============== LC412. Fizz Buzz ================

// ! =============== LC14. Longest Common Prefix ================

// ! =============== LC28. Find Index of First Occurrence ================

// ! =============== LC205. Isomorphic Strings ================

// ! =============== GFG. Some Problem ================

// ! =============== PALINDROME NUMBER ==================
```

This makes it easy to identify **what the problem is and where it came from**.

# 🔥 Multiple Approaches

When a problem can be solved in different ways, I may implement multiple approaches.

For example:

```java
public static String longestCommonPrefixOptimal(String[] strs) {
    // Optimal approach
}

public static String longestCommonPrefixBrute(String[] strs) {
    // Brute-force approach
}
```

### 📈 Approach Progression

<p align="center">

<b>🐌 Brute Force</b>
  →   <b>⚡ Better</b>
  →   <b>🚀 Optimal</b>

</p>

<details>
<summary><b>Why keep multiple approaches?</b></summary>

<br>

Keeping multiple approaches helps me understand:

-   Why the brute-force solution works
-   What makes an approach inefficient
-   How the solution can be improved
-   Which data structures or patterns help
-   How time and space complexity change

Instead of only remembering the final solution, I can understand the **evolution of the solution**.

</details>

# ⏱️ Complexity Analysis

While solving problems, I focus on understanding both **time complexity** and **space complexity**.

<details>
<summary><b>⏱️ Common Time Complexities</b></summary>

<br>

```text
O(1)        → Constant
O(log n)    → Logarithmic
O(n)        → Linear
O(n log n)  → Linearithmic
O(n²)       → Quadratic
O(2ⁿ)       → Exponential
O(n!)       → Factorial
```

</details>

<details>
<summary><b>💾 Common Space Complexities</b></summary>

<br>

```text
O(1)
O(n)
O(n²)
...
```

</details>

The objective is to gradually develop the ability to identify inefficient solutions and optimize them.
